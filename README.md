# GrimDice Desktop 2.1

GrimDice — самостоятельная готическая настольная игра и приложение мастера для 5e: постановочные бои, экспедиции, постоянный Бастион, отряд из пяти героев, отношения, стресс, свет, добыча, последствия кампании, детерминированный импорт статблоков, визуальные моды и защищённый сетевой стол.

Проект использует собственные интерфейс, названия и тексты. Встроенная графика намеренно заменена сверхлёгкими нейтральными заглушками: мастер загружает свои фоны, портреты, токены и эффекты через медиатеку. Проект вдохновлён общими приёмами готической сценической подачи и циклом «убежище → экспедиция → последствия», но не копирует чужие ассеты, персонажей, реплики, музыку или точный интерфейс.

## Быстрый запуск

### Из исходников — Windows, Linux, macOS

Требуется Node.js 22.12+:

```bash
npm install
npm run desktop
```

Локальный веб/LAN-сервер без оболочки Electron:

```bash
npm start
# http://localhost:4173
```

## Сборка под платформы

```bash
npm run pack:windows  # NSIS Setup x64
npm run pack:linux    # AppImage + DEB x64
npm run pack:mac      # universal DMG + ZIP
```

Собирать рекомендуется на целевой ОС. Подписанную и notarized macOS-сборку необходимо выпускать на macOS с сертификатом Apple. При нехватке памяти Windows-сжатие уже ограничено уровнем 3 в `desktop/build.cjs`; вручную можно задать `ELECTRON_BUILDER_COMPRESSION_LEVEL=3`.

### Единый релиз для трёх ОС

Workflow [`.github/workflows/release.yml`](.github/workflows/release.yml) запускает тесты и собирает один GitHub Release на нативных раннерах:

- `GrimDice-<version>-Windows-x64-Setup.exe` — установщик NSIS;
- `GrimDice-<version>-Linux-x86_64.AppImage` и `GrimDice-<version>-Linux-amd64.deb`;
- `GrimDice-<version>-macOS-universal.dmg` и updater-совместимый `.zip`;
- `latest.yml`, `latest-linux.yml`, `latest-mac.yml`, blockmap-файлы и `SHA256SUMS.txt`.

Версия тега обязана совпадать с `package.json`. Пример выпуска:

```bash
npm version 2.1.0 --no-git-tag-version
npm test
git add -A && git commit -m "Release 2.1.0"
git push origin main
git tag v2.1.0
git push origin v2.1.0
```

Можно также запустить **Build and publish installers** вручную в GitHub Actions и указать `v2.1.0`. Сборки сейчас намеренно не подписываются. Позже workflow можно подключить к Windows code-signing и Apple Developer ID/notarization через зашифрованные GitHub Secrets без изменения форматов установщиков.

### Обновления приложения

Установленная desktop-версия проверяет GitHub Releases после запуска и каждые шесть часов. В боковом меню есть экран статуса, ручная проверка, загрузка и команда «перезапустить и установить». Обновление также устанавливается при выходе после загрузки. В режиме разработки механизм отключён; Linux-автообновление предназначено прежде всего для AppImage, а DEB обновляется установкой нового пакета.

## Игровой цикл

### Экспедиция

- ровно пять боевых рангов для героев;
- маршрут с обычными переходами и авторскими развилками;
- явно выбранная ветка и пометка пропущенных узлов;
- свет, провизия, факелы, лекарства, инструменты и ключи;
- бои, опасности, находки, лагеря, элита и владыки;
- стресс, проверки решимости, надлом, доблесть и кризисы;
- добыча из пользовательского справочника или безопасной встроенной таблицы;
- распределение трофеев между героями;
- нераспределённая добыча автоматически уходит в хранилище Бастиона.

### Бастион

- районы с уровнями и стоимостью улучшений;
- назначения героев в Лазарет, Братство клинка, Скрипторий, Костровой двор и другие пользовательские здания;
- эффекты смены: лечение, снятие болезней/стресса, временные хиты, восстановление ресурсов;
- личные инвентари героев и общее хранилище;
- симметричные отношения каждой пары от −100 до +100;
- вражда повышает стресс в бою, преданность снижает его, а хорошие узы усиливают лечение;
- разговоры в лагере и совместная смена у костра развивают отношения.

## Постановочная боевая сцена

- две шеренги, по пять рангов каждая;
- способности с ограничениями исходной и целевой позиции;
- перемещение и нарушение порядка бойцов;
- выбор цели кликом, полноэкранный режим и панель активного бойца;
- сверхлёгкие встроенные заглушки и загружаемые мастером фоны, портреты, токены и эффекты;
- хиты, состояния, стресс, свет, раунд и активный ход на одном экране;
- анимации попадания/лечения и декларативные анимационные моды.

Пример позиционного действия в импортируемом тексте:

```text
Выпад. Атака +7, урон 1d8+4 колющий, из позиций 1-2, цели 1-3.
Теневая стрела. Атака +6, урон 2d6 некротический, из позиций 3-5, цели 1-4.
```

## Честный импорт персонажей

Парсер не использует LLM и не додумывает отсутствующие данные:

- принимает чистый русский или английский текст;
- сохраняет исходник дословно в листе;
- извлекает только явно найденные поля;
- показывает аудит найденного и предупреждения о пропусках;
- распознаёт имя, класс/вид, уровень, КД, хиты, скорость, характеристики, спасброски, Сл, атаки, урон, лечение, защиты и позиции;
- находит счётчики `2/2`, `1/1`, восстановление коротким/долгим отдыхом и перезарядку;
- оставляет каждое значение доступным для ручной проверки и редактирования.

```text
Имя: Сестра Мирен
Класс: Жрец 5
Раса: Человек
КД: 18
Хиты: 38/38
Скорость: 30
Бонус мастерства: +3
СИЛ 14, ЛОВ 10, ТЕЛ 16, ИНТ 11, МДР 18, ХАР 13
Спасброски: МДР +7, ХАР +4
Сл заклинаний: 15
Атака заклинанием: +7
Ресурсы: Божественный канал 1/1 (короткий отдых)

Действия:
Булава. Атака +5, урон 1d6+2 дробящий, из позиций 1-2.
Священное пламя. Спасбросок ЛОВ Сл 15, урон 2d8 излучение, цели 1-5.
Лечение ран. Лечение 1d8+4.
```

## Автоматизация 5e

- профили правил 2014 и 2024;
- криптографически равномерные броски костей;
- атаки `d20 + бонус` против КД, натуральные 1/20 и критический урон;
- преимущество, помеха и укрытие +2/+5;
- атаки заклинаниями и спасброски против Сл;
- полный или половинный урон при спасброске;
- временные хиты, сопротивление, иммунитет и уязвимость;
- лечение, урон, проверки, концентрация и спасброски от смерти;
- периодические кровотечение, яд, ужас и регенерация;
- ресурсы `N/N`, короткий/долгий отдых и перезарядка 5–6;
- инициатива, раунды, свободные формулы и журнал расчётов;
- декларативные операции `damage`, `heal`, `stress`, `condition`, `move`, `light`, `bleed`, `blight`, `horror`, `regen`.

GrimDice автоматизирует общее ядро и только явно записанные свойства. Закрытые тексты книг не встроены; редкие исключения остаются решением мастера.

## Конструктор и визуальный моддинг

В приложении редактируются способности, существа, предметы, эффекты, локации, события, здания и узлы маршрута. Пользовательские пакеты не исполняют код.

Медиатека разделена на:

- спрайты и токены;
- портреты;
- боевые фоны;
- карты;
- визуальные эффекты;
- звуки и музыку;
- шрифты;
- JSON-определения анимаций;
- темы на CSS-переменных;
- JSON-локализацию.

### Встроенный редактор изображений

Раздел «Фоторедактор» работает локально на Canvas API и не отправляет изображение внешнему сервису. Мастер может:

- импортировать PNG, JPEG, WebP или GIF перетаскиванием либо через диалог;
- выбрать соотношение кадра, размер до 4096 px, поворот и отражение;
- менять яркость, контраст, насыщенность, тон, сепию, монохром и размытие;
- применять готические пресеты, виньетку, зерно, тонирование и рамку;
- удалять однотонный фон хромакеем и добавлять подпись;
- сравнивать с исходником, отменять/возвращать изменения и сбрасывать параметры;
- экспортировать PNG/JPEG/WebP или сразу сохранить результат в выбранную категорию IndexedDB-медиатеки.

Пакет `grimdice-mod` v2 включает объекты Конструктора и бинарные файлы. Подробная схема и готовые примеры находятся в [`docs/MODDING.md`](docs/MODDING.md) и каталоге [`examples`](examples/).

## Защищённая сеть: LAN, Hamachi, интернет

1. Мастер запускает desktop-приложение или `npm start`.
2. В окне «Подключить стол» он создаёт код комнаты и получает ключ владельца.
3. Игроки открывают показанный LAN/Hamachi-адрес мастера и вводят тот же код.
4. Каждый игрок выбирает свободного героя; один герой не может быть занят двумя игроками.
5. Мастер управляет противниками, миром, маршрутом, Бастионом и назначениями. Игрок управляет только назначенным героем.

Протокол v2 использует bearer-токены, а для SSE токен передаётся в URL подключения. Записи содержат `baseRevision`; устаревшее изменение получает HTTP 409 и актуальное отфильтрованное состояние. Сервер:

- выдаёт первый ключ владельца мастеру и не позволяет перехватить роль;
- вычисляет членство и владельцев сам;
- скрывает мастерских персонажей, закрытые узлы и чувствительные категории справочника;
- не принимает от игрока изменения маршрута, Бастиона, отношений и чужих персонажей;
- допускает расход собственного инвентаря, но не создание предметов;
- позволяет мастеру снять назначение или переопределить состояние.

Состояние комнаты хранится в памяти процесса. Для публичного интернета `server.mjs` можно развернуть за HTTPS reverse proxy на VPS/домене; отдельный коммерческий relay в локальную поставку не входит.

Основные API:

```text
POST   /api/rooms/:code/session
DELETE /api/rooms/:code/session
GET    /api/rooms/:code/state
POST   /api/rooms/:code/state
GET    /api/rooms/:code/events
GET    /api/health
```

## Сохранения и бинарные ассеты

Кампании сохраняются через нативные диалоги в `.grimdice.json`. Большие ассеты находятся в локальной IndexedDB, поэтому обычный JSON кампании остаётся компактным. Для переноса контента вместе с ассетами экспортируйте полный `.mod.json` v2 в Конструкторе.

## Тесты

```bash
npm test
npm audit --omit=dev
```

`npm test` выполняет синтаксическую проверку renderer/server/Electron-файлов, smoke девяти экранов, контракт редактора изображений и интеграционный тест сетевой authority-модели. Renderer smoke проверяет развилку, пропуск узла, добычу, назначения, отношения и все категории медиатеки. Network smoke проверяет аутентификацию, фильтрацию, эксклюзивное владение, ревизии/конфликты и серверную защиту новых схем. CI дополнительно валидирует конфигурацию пакетирования на Node.js 22.

## Ограничения выпуска

- Windows/macOS-сборки без сертификатов ОС не имеют цифровой подписи и могут вызвать предупреждение системы.
- Подписанный/notarized macOS-релиз создаётся только на macOS.
- Медиафайлы не пересылаются через комнату автоматически; участники устанавливают один и тот же пакет мода либо используют ассеты, встроенные в опубликованный хост.
- Приложение не заменяет книги правил и решение мастера.
